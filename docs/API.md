# API contract v0 — shared implementation boundary

All API routes (except GET /health) require Authorization: Bearer <per-run token>. Bind 127.0.0.1; token passed to Python by env AUDIOHELPER_TOKEN, data dir AUDIOHELPER_DATA_DIR. Python entry `uv run --project backend python -m audiohelper --port N` from repo root, or backend .venv Python with PYTHONPATH backend/src. Desktop main chooses free port, spawns, polls health before exposing connection through preload. No secrets in renderer storage.

JSON camel_case? **Use snake_case throughout API.** IDs strings. Times integer milliseconds relative to recording audio timeline, pauses excluded for v0. HTTP error detail string. All return shapes below mandatory; additional fields allowed.

- GET /health → {status:"ok"}
- GET /logs?limit=100 (positive integer) → `{entries,capacity,dropped}`; authenticated, installation-local, newest first. Each entry has exactly `{sequence,at_ms,operation,provider,model,attempt,elapsed_ms,outcome,status,retrying,usage}`. Only non-negative integer input/output/total token counters; no payloads, headers, exception messages, URLs or credentials. Bounded in-memory ring (default256), reset on backend restart, not durable history. HTTP request-scoped chat attempts and legacy/local ASR calls are connected; Soniox WebSocket attempts and renderer UI are not yet connected. Operation labels: `provider text completion` and `provider audio transcription`.
- GET /settings → {asr:Profile,agent:Profile,notes:Profile,transcript_language:"auto",output_language:"ru",cloud_consent:false}. Profile {provider,model,base_url?,has_api_key?:bool}. Never return keys. Defaults asr local-whisper/small; agent and notes openrouter/empty (unconfigured).
- PUT /settings body same keys partial; profiles optionally api_key for write only; response sanitized full settings. Reject incompatible known ASR model/task profiles. Provider names: local-whisper, local-gigachat-mlx, openai, openrouter, anthropic, openai-compatible. Local providers never require a cloud key or cloud consent. Optional local development connector claude-code ONLY if explicitly enabled, tools disabled and not advertised as third-party OAuth. Do not implement token extraction.
- GET settings includes `used_languages: string[] | null` and read-only `supported_languages: string[]`. PUT used_languages accepts 1..all distinct supported ISO codes; omitted/null preserves, invalid input422 atomically. Desktop requires selection before first Record. First native open freezes the list; GET live exposes it. Historical/direct legacy WS null retains auto behavior; a selected list sends Soniox language_hints + language_hints_strict=true (best-effort). See [recording config](SONIOX-RECORDING-CONFIG.md).
- Native recording preferences in GET/PUT /settings: `native_recording_mode: "transcription"|"translation"|"audio_only"` (default `transcription`), `translation_target_language: string` (default `ru`). Omitted/null PUT fields preserve values; switching mode retains the last target. Codes must match `[a-z]{2,3}(?:-[A-Za-z0-9]{2,8})*`, maximum32characters; this validates syntax, not provider language support. Invalid requests return422 without partial persistence. Existing settings JSON receives defaults without changing other settings. First native open now persists an immutable per-recording configuration; subsequent opens/rotation/restart use that configuration, not current preferences. GET /sessions/{id}/live exposes `recording_mode` and `translation_target_language`. Audio-only skips Soniox key lookup/network; translation passes the stored target to Soniox. Saving preferences alone never enables consent, verifies a model or reprocesses audio. Settings → System now exposes mode/target for new recordings; translated monologues are primary with collapsed originals. See [native recording config](SONIOX-RECORDING-CONFIG.md).
- GET /models?provider=P&task=asr|agent|notes → {models:[{id,name,input_modalities:string[],output_modalities:string[],verified:bool,asr_contract?:"dedicated"|"legacy",note?:string}],error?:string}. No speculative family list. For unknown custom ASR demand supported adapter metadata; audio-input catalog alone not verified ASR. Exact GigaChat entry is `local-gigachat-mlx` / `ai-babai/gigachat-audio-mlx`; it is an unverified audio-language legacy option with chunk timing only, not contextual Whisper finality.
- GET /models/local/status?provider=P&model=M checks dependency, host support and an offline-only local load. It never downloads. States are not_installed, installing, verifying, ready, dependency_missing, unsupported, or error; progress contains measured bytes/files when the SDK reports them. `cached` independently reports whether the fixed allowlisted repository has complete, partial, or lock artifacts, so unsupported/dependency-missing models can still be deleted safely.
- POST /models/local/prepare {provider,model} is the only UI-triggered weight download path. It requires an exact allowlisted identity and reports ready only after a network-closed load. Install backend extras explicitly: `uv sync --project backend --extra local-asr` for Whisper or, on Python 3.12/3.13, `uv sync --project backend --extra local-gigachat-mlx` for pinned `gigachat-audio-mlx==0.1.4`; status/inference never install dependencies implicitly.
- DELETE /models/local {provider,model,confirmation_model} removes only the exact allowlisted repository after confirmation. It rejects active install/verification/inference and unsafe cache paths. The default Hugging Face cache is shared, so the response/UI warns that deletion may affect other applications; set `AUDIOHELPER_MODEL_CACHE` for an app-specific cache.
- GET /sessions → {sessions:[Session]}
- POST /sessions {title:string} → Session
- GET /sessions/{id} → {session:Session,segments:Segment[],messages:Message[],notes:Note|null}
- GET /sessions/{id}/live includes `final_stream_tokens` and replaceable `partial_stream_tokens`: original and translated words in provider order within each final/tail projection, tagged `translation_status: "none"|"original"|"translation"`. Existing original/translation arrays remain available. Translation has no invented timestamps/source IDs; original IDs remain unchanged. Pre-v5 events have no reconstructed mixed order, so stream arrays may cover only newer data. These are ordering evidence, not word/monologue alignment. See [translation storage](SONIOX-TRANSLATION-STORAGE.md).
- PATCH /sessions/{id} {status:"recording"|"paused"|"stopped",title?:string} → Session
- GET live additionally exposes `final_translation_projection` (monologues with original/translation/passthrough token IDs, unassigned translation IDs, connections missing full ordered coverage). This is conservative final-only chunk ownership, not word alignment, partial/live rendering, or completeness. Raw token/source fields are unchanged; see [projection contract](SONIOX-TRANSLATION-STORAGE.md).
- GET live also exposes `live_translation_projection`: per-connection final prefix + replaceable tail, monologue links and `original_tokens`/`translation_tokens`. Both projections include ordered `display_token_ids` interleaving assigned translation and none passthrough. Tail IDs are snapshot-local slots, never source/edit identities; interrupted tails remain non-final. Translation-mode UI consumes the live projection, keeps originals collapsed and shows unassigned translations separately. It never substitutes originals while waiting. Source citations reveal original text; no translation-completeness guarantee is implied.
- DELETE /sessions/{id} → {deleted:true}
- POST /sessions/{id}/audio?sequence=N&start_ms=N&end_ms=N Content-Type audio/wav body standalone PCM16 mono WAV (device sample rate accepted, backend resamples local ASR as needed), ≤30sec; response {segments:Segment[],duplicate:bool}. Sequential processing per session; UI bounded pending queue and displays pending count. Persist actual audio and dedupe sequence, reject sequence reuse with changed content; don't lose failed chunks. No WebSocket required in v0: returned chunk segments visible while subsequent chunks record.
- POST /sessions/{id}/ask {question:string,window_minutes:5,scope:"auto"|"recent"|"all"|"beginning"|"search",language?:string} → {answer:string,citations:Citation[],context:{start_ms:int,end_ms:int,scope:string},model:string}. Nonstream response v0; isolate requests so ASR continues. Future streaming optional, not invented in UI. Save question/answer as Message. auto must recognize explicit minutes and beginning in question before default window, topical search across recording for referential questions. Safe refusals for no transcript. Bound context and show truncation if needed.
- POST /sessions/{id}/notes {language?:string} → Note
- GET /sessions/{id}/audio/{sequence} → original WAV (authenticated) for playback.

Session {id,title,created_at:string,status, duration_ms:int}; Segment {id,start_ms,end_ms,text,language?:string}; Message {id,role:"user"|"assistant",content,created_at,citations?:Citation[]}; Citation {segment_id,start_ms,end_ms,text}; Note {content,created_at,model,citations:Citation[]}.

Tests exercise these public seams with fake external gateway only in deterministic tests; real integration is a separate command. No mocks enabled by default in shipped app. Contract changes require coordinator update before other agent depends on them.
