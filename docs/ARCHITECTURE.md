# Архитектура — стартовое решение

## Процессы
- Electron main: жизненный цикл Python, разрешения, безопасный preload bridge, секреты через OS-backed storage, ограниченная IPC-поверхность.
- React renderer: устройства, запись/транскрипция, агентский чат, конспект, профили моделей. Node integration выключена, context isolation включена, CSP обязательна.
- Python: ingestion, ASR-адаптеры, временной индекс, model gateway, контекст/конспекты, SQLite.
- Локальный HTTP/WebSocket transport с loopback bind, случайным токеном на запуск и проверкой origin. Не открывать backend в сеть. Порты и handshake определяются при реализации.

## Аудиопуть
Выбранный микрофон → ограниченные буферы PCM с sequence ID и монотонным временем → backend → ASR → partial/final transcript events → SQLite/UI.

Для batch-only ASR допустима транскрипция независимых коротких WAV-окон с честной меткой «chunked», не ложный streaming. Не отправлять произвольные куски WebM как самостоятельные файлы. VAD/перекрытие/дедупликацию добавлять после измерений. Очередь ограничена; перегрузка и пропуски видны. Остановка дожидается обработки хвоста. Отключение устройства/провайдера не уничтожает сохранённую запись.

## Домен
Session; AudioChunk(sequence, start_ms, end_ms); TranscriptSegment(id, revision, status, start_ms, end_ms, text, language); ModelProfile(task, provider, model_id, capabilities); ChatMessage; NoteRevision; Citation(segment_id, time_range).

Время записи отделено от системных часов. Политика пауз и границы доступного текста явно отражаются в UI. Partial-текст не считается окончательным источником.

## Контекст агента
1. Снять snapshot последнего обработанного времени на момент вопроса.
2. Определить режим: recent, explicit range, beginning, topic search, whole session.
3. Получить соответствующие final-сегменты; recent не заменяется всей записью. Небольшой соседний контекст допускается только с обозначением.
4. Составить ограниченный по токенам контекст с ID/таймкодами. SQLite range queries + FTS5 сначала; embeddings — только при доказанной необходимости.
5. Стримить ответ. Проверить существование/принадлежность ссылок; объяснения вне записи маркировать отдельно. Ссылки сами по себе не гарантируют достоверность — это проверяется eval.

Read-only инструменты: recent_transcript, transcript_range, search_transcript, read_notes. Лимит шагов/токенов/таймаутов. Инструкции внутри транскрипции игнорируются. Запись/ASR продолжаются независимо от LLM. Не пересылать всю историю при каждом вопросе.

## Конспект
Итоговый конспект строится по первичной транскрипции, с секциями и источниками. Для длинных сессий — иерархическое сжатие с сохранением источников. Live-конспект обновляется пакетами, не каждый аудиокадр.
