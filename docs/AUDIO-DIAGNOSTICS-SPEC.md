# Диагностическое аудио: подтверждённое уточнение

Пользователь завершил grill-me и разрешил реализацию первого среза. Новые требования дополняют ASR-RELIABILITY-SPEC.md; подтверждение НЕ означает готовность.

## Порядок
1. Сохранение всего захваченного аудио и диагностический плеер: приоритет сейчас.
2. Измерения на речи/тишине, исправление сегментации, единый поток текста.
3. Пометки сомнительных участков, ручная постпроверка и исключение из контекста агента.

## Срез 1
- Сохранять всю захваченную запись локально: речь, тишину, шум и будущие VAD-отклонённые участки. VAD не удаляет исходное аудио. Сохранение не зависит от успешности ASR. Паузы пользовательской записи не выдавать за захваченное аудио.
- Плеер всей записи с переходом по таймкодам; видимые границы аудиокусков, поступавших в ASR. При клике на текст по умолчанию воспроизводить соответствующий исходный кусок целиком; отдельное «С контекстом» включает соседние участки. Контекст не меняет эталонные границы кусочка.
- Плеер доступен и при пустой/ошибочной транскрипции, иначе тишину с ошибкой ASR нельзя диагностировать. Ошибки/недостающие файлы/разрывы явно видимы, не маскируются пропуском или сгенерированной тишиной. Тишина, реально присутствующая в исходнике, сохраняется.
- Различать original captured WAV и реально преобразованный вход модели (например local ресемплирует). Нельзя заявлять побайтовую идентичность входу модели без сохранённого доказательства; для старых записей не выдумывать историю provider/model/settings.
- Ограниченная память, безопасный Electron bridge без токена в renderer; освобождать Blob URLs, останавливать воспроизведение при смене/удалении сессии. Прослушивание не запускает ASR и не отправляет аудио в облако.

## Срезы 2–3, позже
- Границы транспортных буферов НЕ границы предложения. Текст единым потоком, timestamps/source links сохранены, provisional может уточняться. Сегментацию выбираем измерениями, не одним dB-порогом: расстояние/шум меняются; VAD не детектор завершённости предложения.
- Подозрительная транскрипция остаётся видимой с пометкой, но до подтверждения исключается из Q&A/notes. Агент предупреждает о пробелах и ссылается на проблемное аудио; не додумывает ответ.
- Постпроверка сначала по кнопке: повтор ASR по аудио с контекстом, той же или выбранной моделью, сравнение старого/нового, без молчаливой замены. Автопометки возможны после оценки сигналов; платные повторы только по разрешению. LLM не реконструирует неслышную речь.

## Выполнение

Пробелы/устаревшее сверять напрямую, не считать граф доказательством отсутствия кода. Реальные source/test evidence, не самоотчёт модели. Доступ MCP уже подтверждён `codex mcp list`.

No commit/push/private audio/mic/cloud without explicit permission. Синтетические PCM тесты допустимы для сохранения/плеера, НЕ как качество ASR. Предыдущие backend language/activity-log RED блокеры сохраняются в отчёте отдельно.
