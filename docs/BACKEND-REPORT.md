# Backend report

Owner: backend agent. Files owned: `backend/**`, this report. Nothing else was modified; nothing was committed.

## Что сделано

Полностью рабочий типизированный FastAPI-бэкенд по `docs/API.md`, запускается как отдельный процесс:

```bash
AUDIOHELPER_TOKEN=<per-run token> AUDIOHELPER_DATA_DIR=<dir> \
  uv run --project backend python -m audiohelper --port 8791
```

Процесс печатает в stdout строку `{"event": "listening", "host": "127.0.0.1", "port": N}`, затем desktop main опрашивает `GET /health`. `--port 0` (по умолчанию) выбирает свободный порт сам.

### Реализованные маршруты (все из контракта)

| Маршрут | Статус | Замечания |
|---|---|---|
| `GET /health` | ✅ | без авторизации |
| `GET/PUT /settings` | ✅ | частичные обновления профилей, ключи только на запись |
| `GET /models?provider=&task=` | ✅ | живой каталог + дисковый кэш, `verified` честный |
| `GET/POST /sessions` | ✅ | список отсортирован новыми вперёд |
| `GET/PATCH/DELETE /sessions/{id}` | ✅ | `DELETE` удаляет строки БД и WAV-файлы |
| `POST /sessions/{id}/audio` | ✅ | идемпотентность по sequence, durable chunks, bounded queue |
| `GET /sessions/{id}/audio/{sequence}` | ✅ | оригинальные байты для воспроизведения |
| `POST /sessions/{id}/ask` | ✅ | временные окна, поиск темы, цитаты |
| `POST /sessions/{id}/notes` | ✅ | иерархическое сжатие длинных сессий |

Ответы — snake_case, ID строковые, время в мс от начала записи, `detail` у ошибок всегда строка (включая 422 — стандартный список pydantic перекрыт обработчиком).

### Ключевые решения

- **Хранение:** SQLite (WAL) + FTS5 для поиска по транскрипции. Аудио пишется на диск **до** вызова ASR, поэтому сбой провайдера не теряет чанк.
- **Идемпотентность:** `(session_id, sequence)` — первичный ключ; тот же sequence с тем же sha256 → `duplicate: true` без повторного вызова провайдера; тот же sequence с другим аудио → `409`.
- **Очередь:** обработка чанков сессии строго последовательная (per-session lock), глубина ограничена `max_pending_chunks=8`; переполнение → `429`, в ответе `pending` для индикатора в UI.
- **Хвост при остановке:** `PATCH status=stopped|paused` ждёт текущую обработку и повторяет чанки со статусом `failed`/`pending`.
- **Конкурентность:** ASR и LLM-запросы независимы — вопрос и конспект не блокируются очередью транскрипции (проверено и тестом, и живым прогоном).
- **Секреты:** keyring (OS keychain) с fallback на переменные окружения (`OPENROUTER_API_KEY`, `OPENAI_API_KEY`, `ANTHROPIC_API_KEY`). Ключи не попадают в БД, ответы и логи; в API только `has_api_key`. Никакого извлечения чужих токенов, коннектор claude-code не реализован (по решению пользователя).
- **Безопасность транспорта:** bearer-токен на все маршруты кроме `/health` (сравнение через `hmac.compare_digest`), проверка `Host` (только loopback) и `Origin` (loopback/`file://`/`null` + список из `AUDIOHELPER_ALLOWED_ORIGINS`).
- **Согласие на облако:** при облачном ASR-провайдере и `cloud_consent=false` загрузка аудио отклоняется с `400`.

### Честность возможностей моделей

Разделены два вопроса:

- **Совместимость** (проверяется при `PUT /settings`): текстовая модель для ASR отклоняется по каталогу (`400`), Anthropic для ASR отклоняется, `local-whisper` для agent/notes отклоняется, неизвестный чекпойнт whisper и не-transcription модель OpenAI отклоняются. Если каталог недоступен и кэша нет — профиль принимается, но остаётся неподтверждённым (доказать несовместимость офлайн нельзя).
- **`verified`**: `true` только после реально успешного вызова именно в этой установке; в `verification_note` — что и когда подтверждено. Наличие `audio` во входных модальностях каталога **не** считается доказательством ASR — это подтверждено практикой: `nvidia/nemotron-3-nano-omni-30b-a3b-reasoning:free` заявляет audio-вход, но вернул HTTP 400 на реальный запрос.

## Ограничения и что не проверено

1. **local-whisper не запускался.** Адаптер написан (faster-whisper, ресемплинг в 16 kHz, ленивая загрузка, кэш модели), но веса не скачивались: `faster-whisper`/`numpy` — опциональный extra `local-asr`, а загрузка весов требует явного `AUDIOHELPER_ALLOW_MODEL_DOWNLOAD=1`. Реальной локальной транскрипции не было — профиль честно остаётся `verified: false`.
2. **OpenAI ASR и Anthropic chat** покрыты только тестами через mock-транспорт; живых ключей нет, живого вызова не было.
3. **Стриминга нет** (по контракту v0). Ответ агента одноразовый; UI видит сегменты чанка сразу после его обработки.
4. **Стоимость и токены не сохраняются** — `usage` из ответов провайдера не пишется в БД. Для бюджетов из PRODUCT.md это нужно добавить.
5. **SQLite вызывается синхронно** внутри async-обработчиков (локальный однопользовательский объём). Долгие операции (ASR, LLM) идут вне блокировки.
6. **`duration_ms` сессии** берётся из заявленного рекордером `end_ms` чанка, а границы сегмента ограничены фактической длительностью аудио — при расхождении заявленного окна и реального аудио они отличаются.
7. **Поиск по теме** — FTS5 с префиксным усечением словоформ (простая эвристика для русского), без стемминга и эмбеддингов. На редких формах может промахнуться.
8. **Не проверено на реальной русской и смешанной речи**, WER/CER не измерялся, микрофонный путь и Electron — зона UI-агента.
9. Данные живого прогона лежат в `.runtime/` (в .gitignore): `live-check.json`, `live-data/`, `live-backend*.log`. Персональных записей нет, секреты не печатались.
