# Experimental ASR: согласованные CRITIC-критерии

Пользователь подтвердил общее понимание и разрешил исследование/исправления после grill-me. Этот документ уточняет прежние LOCAL-CONTEXT-MODE/LIVE-* контракты; перечисленное ниже — требования, НЕ утверждение о реализации.

## CRITIC
- ASR не прекращает работу молча. При сбое capture и сохранение исходника независимы от ASR; сохранённый текст/аудио не теряются. Storage failure должен быть явно показан, нельзя обещать запись без исправного хранилища.
- Явные действия: повторить обработку либо продолжить обычным режимом. Никакого скрытого fallback. Переход сохраняет материал, обрабатывает непокрытый участок без пропусков/дублей и не обходит защиту final writer; облачная передача требует соответствующего согласия.
- Драфт автоматически сохраняется и восстанавливается при повторном открытии и после аварийного закрытия. Незавершённая обработка видна и возобновляема. Микрофон после перезапуска сам не включается; возможный несохранённый участок нельзя скрывать.
- Автоматически уточняется только черновой хвост. Подтверждённый текст и ручные исправления защищены от перезаписи.
- Исправить можно во время формирования драфта; изменение защищает фрагмент, не блокируя новую речь. Принять фиксирует текущий вариант и доступно ТОЛЬКО после завершения обработки данного законченного фрагмента, не всей записи. Сохранение не зависит от Принять. Обработка без ручного принятия завершается автоматически.
- При ошибке/зависании финализации Принять остаётся disabled с причиной; доступны исправление, повтор и явный переход обычного режима. Ручная правка не означает успешную финализацию.
- Границы фрагментов — речь/контекст и завершение обработки, не транспортный чанк и не принудительный таймер. Остановка записи должна завершить обработку хвоста либо явно сообщить ошибку с восстановлением, а не бесконечный драфт.
- Исходное аудио сохраняется полностью, включая тишину. Нет пустых карточек/выдуманного текста в транскрипте. Чистая тишина не запускает decoder; новая речь автоматически обрабатывается без обрезания начала. Ожидание речи отличается от сбоя.
- На той же реальной записи итоговое качество experimental не хуже обычного по существенным ошибкам: пропуски/выдуманные фразы/числа/отрицания/термины. Начальные ошибки драфта допустимы только как временные. Пример пользователя: Unit 1 recording 7 ошибочно показано You need one recording; причина и итог не проверены.
- Приёмка: минимум 30 минут реальной речи с паузами, поступление текста до конца, финализация после stop. Повторный вход и авария — отдельные сценарии. Моки проверяют механику, не качество ASR. Сравнение с обычным режимом должно фиксировать фактические модели/настройки; пользователь ранее хвалил cloud, не следует молча считать local legacy эквивалентом этого baseline.

## LOW
Диаризация/спикеры не блокируют этот этап. Прочие LOW после CRITIC.

## Исполнение
Один общий проход связанных путей capture → persistence → scheduler → ASR/finality → API/store/UI. Группировать дефекты по общим причинам, передавать исполнителям компактный проверенный контекст; не перечитывать проект ради каждого симптома. Наблюдаемый RED → исправление → независимая проверка. Не терять исходные незакоммиченные изменения. AGENTS.md определяет модели; без скрытой подмены. Не трогать пользовательские записи/профиль, не включать микрофон и не скачивать веса автоматически. Для реального теста использовать разрешённый материал либо запросить его, не имитировать приёмку.
