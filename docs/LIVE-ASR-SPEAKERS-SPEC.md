# Live ASR и участники — подтверждённое уточнение

Пользователь подтвердил порядок и разрешил первый пункт после grill-me. Это спецификация, НЕ результат приёмки. Дополняет ASR-RELIABILITY-SPEC.md и AUDIO-DIAGNOSTICS-SPEC.md.

## Приоритеты
1. Воспроизводимые проверки речи/тишины; устранение ложного текста без потерь тихой речи; сегментация с контекстом и изменяемым предварительным хвостом.
2. Локальная диаризация: участники, пересечения, ручные правки.
3. Использование надёжного текста и меток участников агентом/конспектом.

## Пункт 1 — разрешён сейчас
- По пользовательскому прослушиванию: ASR выдумывает текст на тишине; независимые 5s окна рвут речь. Это пользовательское подтверждение симптомов, не измеренная частота ошибок.
- Приоритет качества над принудительной финализацией ради скорости. <=3s p95 остаётся целью измерений, не таймером обрыва фразы; отставание видно. Предварительный текст может уточняться; длинный монолог выводится постепенно.
- Внутренние транспортные/памятные буферы необходимы, но их границы не равны концу предложения. Проверить обработку с перекрывающимся контекстом и фиксацией устойчивой части; не терять/дублировать слова. Не считать уменьшение контекста исправлением.
- Приоритет речи поверх шума/музыки/кондиционера/хлопков. Не отбрасывать весь смешанный участок из-за помех. Участок без речи не порождает текст. Один порог dB недостаточен, VAD не определяет завершённость предложения.
- Исходное аудио сохраняется целиком, включая тишину/помехи. Шумоподавление только на копии и только после сравнения качества (может повредить тихую речь). Не внедрять фильтр, который визуально улучшает шкалу, но не качество.
- Пение исключать из разговорной транскрипции; голос ТВ/фонового источника не удалять при неуверенности, обозначать сомнение. В записи лекции/видео он может быть основным. Это отдельный сложный критерий: обычный VAD сам по себе не классифицирует источник; не заявлять решённым без проверки.
- Неясные слова не достраивать LLM. Предварительные фрагменты не источник final Q&A/notes; ранее согласованные ручной повтор по аудио/сравнение/метки сомнения сохраняются.

## Диаризация — после пункта 1
- По голосу, не по смыслу реплик. Устойчивые Участник1/2/... в пределах ОДНОЙ записи, после паузы и при повторном открытии сохраняются; новая сессия начинает заново, без распознавания личности между сессиями.
- Количество участников заранее не задаётся; вычислительные ограничения показывать честно.
- Неуверенная метка: «Участник неизвестен», а не новый номер при каждом изменении голоса.
- Метки live предварительные, уточняются по контексту, итоговая проверка после stop; не задерживать текст ради определения голоса.
- Пересечение голосов отмечается; раздельный текст только если удалось, иначе одновременная речь/неопределённые участники, сохранение разобранных слов/таймкод/прослушивание.
- Локальный режим обязателен; при отставании метки догоняют, ASR не останавливается. Облачная диаризация только по отдельному согласию.
- Ручное переназначение реплики, объединение номеров, отделение реплик в нового участника, отмена. Автоматика не перезаписывает ручное; исходный текст/аудио не меняются.
- Кто что сказал: только надёжные метки, сомнительные реплики отдельно. Надёжный текст с неизвестным говорящим можно использовать для «что обсуждали» без приписывания человеку.

## Проверка и исполнение
SOL использует собственный codebase-memory-mcp, coverage и прямое чтение текущих исходников; ASTRA проектирует и независимо проверяет. Реальные ASR-вызовы на локальной модели отличать от mock тестов механизма. Синтетические тишина/шум допустимы как контролируемые сигналы, НЕ как человеческая речь. Публичная речь с независимым эталоном; пользовательские записи/микрофон только по отдельному доступу/согласию. Никаких скрытых облачных запросов/смены моделей, commit/push/секретов. Реальные ASR API проверки имеют отдельный ранее согласованный лимит$3, не расходовать на локальные тесты.
