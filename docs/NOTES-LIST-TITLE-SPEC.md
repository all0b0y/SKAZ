# Notes: список, заголовок, индикатор генерации

Подтверждено пользователем в grilling-сессии. Решения пронумерованы в порядке, в котором
задавались вопросы; при расхождении с более ранними документами (`NOTES-REDESIGN-SPEC.md`)
побеждает этот файл в пределах перечисленных пунктов.

## Проблема

1. Панель никогда не открывает заметку сама: пока нет вкладки, показывается пустое состояние
   «Нет открытых конспектов», даже если у сессии есть заметки. Единственный вход —
   «+» → «Открыть существующий», о котором нужно догадаться.
2. Заголовка у заметки нет: он вычисляется из первой строки текста, поэтому пустые заметки
   неотличимы друг от друга («Без названия»).
3. Генерация не даёт обратной связи, пока открыта другая вкладка: индикатор рисуется только
   в ветке пустого состояния.

## Решения

### Список заметок вместо пустого состояния

1. Межсессионная загрузка НЕ вводится. Вкладка показывает текст только когда её сессия выбрана
   в сайдбаре — как сейчас. Это осознанно отклонённый вариант, не недоработка.
2. Когда открытых вкладок нет, панель показывает прокручиваемый список заметок текущей сессии.
   Обе кнопки («Создать конспект с ИИ», «Создать пустой») остаются видимыми всегда; пустой
   список — это список без строк, а не другое состояние.
3. Автооткрытия нет. Закрытие вкладки — осознанное действие пользователя, и возврат на экран
   не должен его отменять.
4. Сортировка по `notes.updated_at` (новая колонка), обновляемой при каждом принятом сохранении.
   В строке: заголовок и относительное «изменено …». `created_at` для сортировки не годится —
   только что отредактированная заметка осталась бы внизу.

### Заголовок и переименование

5. Новая колонка `notes.title`. Модель Obsidian: имя — отдельная сущность, переименование НЕ
   трогает текст, а правка текста НЕ переименовывает заметку.
6. Пустой `title` → показывается первая строка текста (`titleFromContent`), как раньше.
7. Санитизация заголовка при сохранении: обрезка пробелов по краям, переносы строк → пробел,
   удаление управляющих символов и `/`, снятие хвостового `.md` (в т.ч. повторного), предел
   120 символов. Если результат пуст — сохранение отклоняется и заголовок ОТКАТЫВАЕТСЯ к
   прежнему значению. Пустое имя не сохраняется никогда.
8. Имя файла проекции остаётся `Note-{id}.md`. Заголовок пишется первой строкой `# …` в тело
   файла. Переименование файлов на диске в этот срез не входит: манифест владения, детектор
   конфликтов и preflight удаления ключуются по этому имени.
9. Переименование — двойной клик по названию вкладки И по строке списка.

### Индикатор генерации

10. Вкладка открывается СРАЗУ, со спиннером и подписью «Генерация…». Записи в БД при этом нет:
    вкладка привязывается к настоящей заметке, когда ответ придёт. Преждевременная пустая
    заметка оставляла бы мусор при каждой ошибке.
11. Поле read-only, пока идёт генерация: сохранять набранное некуда, записи ещё нет.
12. Ошибка генерации — вкладка ОСТАЁТСЯ, показывает причину и кнопку «Повторить». Закрывает её
    пользователь. Общая плашка `notesError` теряет привязку к конкретной генерации.
13. Если вкладку закрыли или пользователь ушёл в другую сессию, а ответ пришёл — заметка просто
    появляется в списке. Вкладка сама не всплывает и сессия сама не переключается.

### Удаление

14. Удаление доступно из строки списка и из области вкладки. Удаление МЯГКОЕ: строка `notes`
    помечается `deleted_at`, пропадает из списка и из папки сессии, но остаётся в БД.
15. Экран корзины, восстановление и «очистить корзину» — отдельная задача, не этот срез.

## Вне среза

Корзина как экран, восстановление, вкладки из разных сессий, переименование файлов проекции,
инструменты «перевести/исправить/стилизовать».

## Изменения контракта

- Схема: `notes.title TEXT NOT NULL DEFAULT ''`, `notes.updated_at TEXT`, `notes.deleted_at TEXT`.
  Миграции — `ALTER TABLE` по образцу `revision`/`source_revision` в `db.py`.
- `PATCH /sessions/{id}/notes/{note_id}` принимает `title` наряду с `content`.
- `DELETE /sessions/{id}/notes/{note_id}` — мягкое удаление.
- Каждая новая пара метод/путь требует записи в `electron/ipcPolicy.ts` `ROUTES` И случая в
  `frontend/src/security/ipcPolicy.test.ts` В ТОМ ЖЕ ИЗМЕНЕНИИ: иначе main-процесс отклонит
  вызов с `method/path not allowed`, а весь остальной набор тестов останется зелёным.
