# Проверка качества

## Предлагаемые публичные границы тестирования
Подтверждены пользователем в текущей сессии, включая отдельную приёмку на реальной речи без моков.

1. Audio ingestion API: получение PCM/файла, порядок/дубликаты/валидация, завершение хвоста, bounded queue, ошибки провайдера.
2. Session/query API: окно 5/10 минут, начало, поиск темы, текущий watermark, пустые данные, изоляция сессий, сохранение/восстановление.
3. Provider gateways: несовместимая ASR-модель отклоняется; корректная обработка streaming/ошибок, независимость трёх профилей, секреты не возвращаются UI.
4. Agent/notes API: ответ и конспект по данным, корректные ссылки, отмена/таймаут, недоверенная транскрипция.
5. Desktop UI: start/pause/stop, устройство и разрешения, видимый текст, чат во время записи, сохранённый конспект.

## Виды проверок
- Детерминированные unit/integration тесты на публичных интерфейсах. Моки допустимы на внешнем сетевом стыке, но не как доказательство качества модели.
- Реальный ASR прогон на человеческой речи с ручной эталонной расшифровкой; RU, EN, смешанная речь. WER/CER + проверка ключевых терминов.
- Live-вопросы по старой и свежей теме, определениям и отсутствующему событию. Оценка соответствия окну, фактам и источникам.
- Конспект: полнота ключевых мыслей, отсутствие выдуманных решений/обязательств, язык.
- Физический микрофон в Electron требует разрешения пользователя. Аудиофайл и fake device не заменяют эту проверку.
- Измерять latency от конца фразы до final, первый токен/полный ответ, время конспекта, CPU/RAM, токены/стоимость. Пороги уточнить после baseline.
- Перед завершением: Python tests/lint/typecheck, frontend tests/typecheck/build, desktop smoke, независимое code review, повтор исправленных проверок.

## Доказательства
Для каждого прогона сохранять команду, exit code, фактическую модель, входной fixture ID/hash, результаты/задержки и ограничения в docs/STATUS.md либо отдельном отчёте. Не коммитить личные записи, секреты и необезличенные логи.
