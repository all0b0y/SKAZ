# Soniox: чистая лента речи — согласованная спецификация

Статус: пользователь подтвердил интервью и переход к проверке API/документации/реализации. Это требования, НЕ отметка о готовности. При конфликте с прежним UI эта спецификация приоритетна; внутренние источники и временные привязки не отменяются.

## Лента
- Один непрерывный ход речи одного спикера — один монолог независимо от длительности, пауз и длины. Смена A→B→A создаёт три монолога. Временная нарезка не отображается.
- Предварительный текст выводится сразу обычным текстом, заменяемый хвост уточняется на месте. Нет draft/pending/final, счётчиков очереди, задержек, отдельных технических карточек. Внутреннюю финальность сохранять; предварительное не становится источником Q&A.
- Первому голосу предварительно назначается Спикер 1; новые provider speaker IDs получают следующие номера. Уточнение принадлежности меняет метку/границы; соседние блоки одного спикера объединяются. Нельзя считать одинаковые IDs разных запросов одной личностью без подтверждения.
- Автопрокрутка следует текущей речи только пока пользователь внизу. Чтение выше и восстановление старого пропуска не сдвигают место чтения; кнопка «К текущей речи» возвращает вниз.
- Временные метки, аудиокнопки и ссылки у монологов скрыты. Отдельный общий плеер: play/pause, перемотка, позиция, длительность, скорость.

## Режимы и перевод
- До старта: Транскрипция / Транскрипция + перевод / Только запись. Во всех сохранять оригинальное аудио.
- Транскрипция и встроенный перевод — Soniox, без выбора текстовой LLM для перевода. Первоначальная идея «любые модели перевода» отменена.
- Язык перевода выбирается до старта, последний выбор сохраняется. Дополнение пользователя: перед первой записью обязательно выбрать используемые языки в настройках (выпадающий список с множественным выбором, от одного до всех поддерживаемых); Soniox получает language_hints + language_hints_strict=true. Это best-effort ограничение, не абсолютное отключение identification. Режим/целевой язык/используемые языки конкретной записи неизменны; настройки меняют только новые записи.
- Только запись не обращается к Soniox; после остановки пользователь запускает обработку с переводом или без него.
- В режиме перевода главный текст — перевод. У каждого монолога закрытое по умолчанию «Посмотреть оригинал». Пока перевода нет, оригинал в основную ленту не подставлять; без статусов ожидания.
- Ассистент/конспекты используют оригинал. Ссылка раскрывает оригинал и подсвечивает конкретные слова, без автоматического воспроизведения аудио.

## Сбои и жизненный цикл
- Сбой Soniox не останавливает сохранение аудио. В ленте на месте пропуска: «Сбой распознавания», безопасная причина, «Возобновить» и длительность пропуска.
- Нажатие разрешает платную обработку всего пропуска без дополнительного диалога. Live новой речи и дораспознавание сохранённого диапазона работают параллельно; результат заполняет собственный пропуск.
- Сбой перевода не останавливает оригинал, ЕСЛИ provider продолжает его отдавать. Оригинал не подменяет перевод. При ошибке всего WS распознавание также недоступно, хотя локальная запись продолжается.
- «Стоп» немедленно прекращает захват; сохранённое аудио доступно, оставшаяся обработка продолжается. Одна компактная строка состояния вне монологов.
- Выход во время обработки требует подтверждения: «Обработка ещё не завершена. Если выйти, она остановится. Записанное аудио и готовый текст сохранятся. Выйти?» Никакого удаления готовых данных. Повторное открытие/пробуждение предлагает «Возобновить»; нет скрытого платного возобновления. Во время сна захват не гарантирован.
- Отказ сохранения аудио останавливает запись и показывает одну причину; ранее сохранённое не удаляется.
- Низкая громкость — одна надпись в фиксированном месте возле управления, без реакции на короткие паузы/сдвига ленты. Уровень сигнала не является детектором речи.
- Технические сведения только в отдельной диагностике; ошибки не раскрывают секреты.
- Штатное «Saving locally» не показывать; ошибки локального сохранения и защита несохранённого аудио остаются видимыми.

## Правки после завершения обработки
- Оригинал и перевод редактируются независимо; правка оригинала не запускает платный перевод и не затирает ручной перевод.
- Переименование спикера — во всей записи, без автоматического переноса личности между записями.
- Через меню имени: объединить спикеров, переназначить один монолог существующему/новому спикеру, разделить монолог в выбранном месте. Структурные действия с отменой, сохранением источников и согласованием оригинала/перевода.
- Если точная граница перевода неизвестна, требуется подтверждение границы, не догадка.

## Инварианты данных
- Единая шкала исходного аудио в samples; provider-relative ms привязаны к началу конкретного запроса. Полуоткрытые диапазоны [start,end) принадлежат конкретной recovery job, результаты коммитятся идемпотентно и не перезаписывают соседей.
- Контекстное перекрытие при повторной отправке не вставляется второй раз. Реальная одновременная речь разных людей не устраняется искусственно.
- Стабильные source IDs/ревизии отделены от визуального монолога. Слияние/разделение/переименование не ломает ссылки. Ответы используют оригинальные источники, не вымышленные тайминги перевода.

## Проверенные официальные API-факты
Проверены по живым страницам браузером; web_extract вернул усечённый/устаревший пример модели, поэтому его пример не основание менять model ID в коде.

1. https://soniox.com/docs/stt/rt/real-time-transcription — non-final заменяются; final больше не меняются. UI не обещает автоматическое исправление любых финальных ошибок.
2. https://soniox.com/docs/api-reference/stt/websocket-api — translation={type:one_way,target_language:...}; transcript и translation один WS; при error response соединение закрывается. Translation tokens НЕ содержат start_ms/end_ms; speaker optional. Завершение пустым frame, затем ответы до finished. До 300 минут аудио на stream.
3. https://soniox.com/docs/translation/stt-translation/rt-translation и https://soniox.com/docs/translation/stt-translation — оригинал/перевод идут в последовательности, но токены НЕ сопоставлены 1:1. Нельзя приписывать словам перевода точные тайминги оригинала по позиции или длине.
4. https://soniox.com/docs/translation/stt-translation/async-translation — перевод записанного аудио поддержан отдельным async job через upload/file_id; результат содержит оригинал и перевод. Это подтверждает путь восстановления из аудио, не text-only retry. Для desktop использовать bounded polling, не публичный webhook. Политика удаления облачных файлов/задач требует проверки перед реализацией.
5. https://soniox.com/docs/stt/concepts/speaker-diarization — временные смены спикера могут стабилизироваться; ранняя endpoint/manual финализация ухудшает диаризацию. До 15 спикеров на transcription session. Гарантия идентичности speaker IDs между независимыми запросами в прочитанных контрактах отсутствует.

## Подтверждённое соответствие спикеров после восстановления
Пользователь согласовал новые номера спикеров после переподключения/отдельного async backfill с ручным объединением с прежними. Одинаковые provider IDs разных запросов автоматически не склеивать. Ключ принадлежности — (request_id, provider_speaker_id), отображаемый номер уникален внутри записи и сохраняется. Новое подключение не сбрасывает счётчик отображаемых номеров. Автоматическое сопоставление личности между запросами не входит в первую версию.

## Последовательность реализации и приёмка
1. Типизированная проекция токенов→монологи, стабильные источники, разделение оригинала/перевода. RED/GREEN на публичной границе: A/B/A, смена provisional speaker, объединение, повтор final, тайминги запросов, отсутствие translation timestamps.
2. Read-only чистая лента, раскрытие оригинала, фиксированные статусы, scroll anchoring, навигация источников. UI tests без фальшивых recovery-кнопок.
3. Persisted режимы и язык; Soniox config, original/translation storage; only-record без cloud calls.
4. Durable recovery jobs: ownership диапазонов, ручной запуск/consent, live+backfill, retries/cancel/restart, несопоставленные спикеры, облачная очистка. Раздельные watermarks оригинала и перевода; не считать job завершённым только по ASR watermark.
5. Плеер/редактирование/revisions/undo/источники, quit/sleep, диагностика, стабильная громкость.
6. Frontend/backend regression, types/lint/build, isolated Electron smoke, самостоятельный review; реальные речь/API/микрофон только в отдельно разрешённой приёмке. Никаких помощников, commit/push.

Первый runtime-срез реализован: speaker/token provenance и чистая лента оригинала с inline tail, source IDs и управляемой прокруткой. Проверен локальными API/UI тестами и offline Electron smoke; результаты в HANDOFF/STATUS. Перевод, режимы, восстановление, редактирование и полная приёмка остаются незавершёнными.
